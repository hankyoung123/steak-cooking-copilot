# 收尾：浮层主按钮，读数簇下移

Verified on 2026-09-29 with Xcode 26.2 / Swift 6.2, iOS 26.2, one iPhone 17
simulator (window 402 × 874).

## 问题回顾

煎制等待时，说明行、进度条、估算/建议都压在牛排最亮的地方。根因不是"遮罩不够黑"，而是
**这一簇的位置**：它下面撑着 248pt 的带（status 112 + 两段间距 + 次级带 + 主按钮带），所以
指令顶落在屏幕 0.61 处，而照片主体在 0.40–0.65。

顺带纠正我早先算错的一个数：会话的**容器不是 874pt**，而是从 y=62 起、约 812pt（探针实测）；
iPhone 17 那一档里 scene 带当时是 304pt（未到 340 上限），所以"把空白搬下去"这种想法在
scene 吸收余量的情况下等于没改。

## 改了什么

1. **主按钮从骨架里搬出去，改成浮层**（`.overlay(alignment: .bottom)`）。它仍是每相位固定
   的一格，探针照旧存在；没有动作时只停止接收触摸，帧不变。
2. **status 带 112 → 96**（轨道 12 + 间距 10 + 两行读数约 90，本来就有余量）。
3. **底部不再为按钮花两段间距**（`bottomActionSpacing` 12 与 `bottomSecondarySpacing` 8）。
   两个字段保留在类型里（结果页还在用），但不再计入会话预算。
4. **余量从 status 之下移到 instruction 之上**：大屏上读数簇贴着底部动作浮层，而不是向上
   飘到照片上。
5. **暗色舞台的合成图放大 1.12 并上移 5% 帧高**（约 44pt），把主体亮部抬出文字带。放大是
   为"上移不露边"服务的：绕中心放大后图像上下各溢出约 45pt，抬 38pt 仍然盖满画面。
6. 主按钮新增 `floating` 样式（更深的投影），读起来是浮在照片上的一块面，而不是印在纸上的
   黑块。

## 实测（布局探针，窗口坐标）

| 元素 | 改前 | 改后 |
| --- | --- | --- |
| 指令顶边 | 534 | **570**（+36） |
| 进度条顶边 | 606 | **642**（+36） |
| 估算/建议顶边 | 630 | **666**（+36） |
| 主按钮顶边 | 783.6 | **783.6**（不变） |
| scene 带 | 304 | 340 |

按钮位置一点没动：浮层的净空（56）恰好等于原主按钮行高，撤销的两段间距（20）加上 status
省下的 16，共 36pt 全部变成了"读数簇下移"。照片主体的亮部同时上移约 28pt（放大 + 上移的
净效果），所以文字与亮部之间的间距一共拉开约 64pt。

## 不变量与验证

- **跨相位槽位稳定**：3 个骨架 UI 走查全部通过，包括
  `testSessionSkeletonSlotsDoNotMoveBetweenCookingPhases`（它逐相位比较 8 个槽位的帧，
  含主按钮；浮层没有破坏它）。
- **按钮探针常驻**：`bottomPrimaryControl` 的固定高度帧仍在，有动作/无动作两种状态下探针
  帧相同，所以"CTA 只有一个位置"这条不变量比之前更强（它不再依赖流式预留）。
- `SessionLayoutMetricsTests` 通过：底部块的算式改为
  `bottomSecondaryHeight + floatingActionClearance`，并断言净空不小于按钮高度；
  `heightExcludingScene` 的求和不再包含那两段间距。
- **时间模型、引擎、文案、素材策略都没有碰。**

## 权衡与已知

- **PREP 不重叠**：Dry/Salt 在流里（737–773），浮层按钮在其下方（783.6–840），相邻约 10pt。
- **照片放大会裁掉边缘**：`CookFlipBackground`（夹子那张）右侧的夹子会被裁掉一部分，见
  `sear-after.png`。若不能接受，把 `compositionZoom` 降到 1.08、`compositionLift` 降到
  0.035 即可（抬升会相应变小）。
- 想再拉开距离的话，下一步杠杆是**把遥测改成单行**（"估算 ~23°C · 建议 52°C"，status 可再
  降约 24pt），或加一层很轻的遮罩；两者我都还没做。
